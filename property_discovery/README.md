# Property Discovery

第一阶段只回答公开市场上是否出现目标面积、价格的住宅挂牌，不推荐购买，不扩展人生规划。

默认：仅贝壳、徐州、40-60平方米、最低价不限（0作为查询下界）、最高50万元，电梯或1-3楼优先。三环边界未知就写未知。0元挂牌需人工核实，不计有效候选。

居住优先级保持原项目定义：安静 > 隔音 > 生活便利 > 价格 > 升值。评分权重不改，本模块不以价格排序代替居住评分；未知安静与隔音不打分。存在性线索不能当作适合长期居住的推荐。

## 运行

需要Python 3.9+标准库、已安装的 `browser-harness` 及可正常连接的Chrome：

```sh
python3 -m property_discovery.discover --target 10
python3 -m unittest discover -s tests -v
```

输出 `candidate_properties.md`、`property_discovery/data/latest.json` 和追加的 `data/runs/<运行ID>.json`。所有来源与失败原因可追溯。每次报告更新，历史运行快照保留。

通过 `--url` 添加已知公开列表地址（重复参数），如下一页。默认仅贝壳2个列表页，最多30套详情，每次读取间隔至少2秒，达到10套贝壳公开字段匹配时停止。`--auxiliary` 可额外读取辅助平台，正式候选仍只计贝壳。没有后台任务，不无限遍历。

## 边界

- 浏览器只执行正常导航及只读DOM提取；不读取Cookie、账号、私信，不访问私有接口、不修改登录状态。
- 使用Chrome现有会话不意味着访问私有内容；仅提取普通在售卡片、公开住宅属性和小区地址。若内容要求登录则记录并停止，绝不登录或规避。
- 验证码、登录墙、反爬页面出现即停止该平台本轮访问，不解验证码、不换IP/账户重试。
- 贝壳列表、详情、小区DOM已验证；房天下列表作为辅助，详情适配器尚未验证，因此卡片只是线索，不参与正式候选计数。安居客暂未验证适配器，明确记录unsupported，不猜字段。
- 公寓及非普通住宅排除；用途或平台产权字段缺失保留在线索，不当作已确认住宅。公开产权字段齐备也不等于登记产权清晰。
- 低/中/高楼层不转成具体楼层；总层数不证明电梯；建筑结构不证明隔音；标题不证明安静。
- 报价仅判断是否在预算内；没有可比成交就不评价格合理性。跨平台相似房源不擅自当作同一套去重。
- 原始HTML、整页文字、身份信息、聊天及经纪人电话不保存。测试数据仅用于测试，不写入真实房源报告。
